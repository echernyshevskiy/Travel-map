# Резервная копия репозитория данных

`backup.yml` — процесс GitHub Actions для **закрытого репозитория данных** (того,
куда приложение синхронизирует `travel-data.json`). В репозитории сайта он не
работает и лежит здесь только как образец.

Раз в неделю он проверяет, что файл данных цел, и, если данные изменились,
создаёт в репозитории данных выпуск (Releases) «backup-ГГГГ-ММ-ДД» с двумя файлами:

- `travel-data-ГГГГ-ММ-ДД.json` — данные на эту дату (можно загрузить в приложение
  через «Импорт»);
- `history-ГГГГ-ММ-ДД.bundle` — вся история репозитория данных одним файлом:
  `git clone history-ГГГГ-ММ-ДД.bundle` восстанавливает репозиторий целиком.

Хранятся последние 12 копий. Если файл данных окажется повреждённым или пустым,
запуск упадёт, и GitHub пришлёт письмо.

## Как подключить

1. Откройте репозиторий данных на GitHub → **Add file → Create new file**.
2. Имя файла: `.github/workflows/backup.yml`.
3. Вставьте содержимое `backup.yml` отсюда целиком → **Commit changes**.
4. Вкладка **Actions** → «Резервная копия данных» → **Run workflow** — первая копия
   появится в **Releases** через минуту. Дальше — каждое воскресенье утром.
