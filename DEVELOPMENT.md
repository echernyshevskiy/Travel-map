# Как устроен репозиторий

С версии 2.55 «Карта путешествий» собирается сборщиком **Vite** (с версии 2.71 — Vite 8, нужен Node.js 20.19+ или 22.12+) из исходников в папке `src/`.
На выходе — тот же один самодостаточный `index.html`: стили, Leaflet, справочники и код внутри
файла, карта работает без сети и открывается с диска.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/index.html` | разметка страницы |
| `src/styles/app.css` | стили |
| `src/app/NN-*.js` | код приложения по разделам (карта, список, синхронизация, бег…); сборщик склеивает их по порядку номеров в один модуль |
| `src/lib/` | независимая логика — настоящие ES-модули с `export`: геометрия и треки (`geo.js`), форматирование, названия и даты (`format.js`), подсчёт визитов (`visits.js`), слияние при синхронизации (`sync-merge.js`), разбор выгрузок Google (`timeline-parse.js`), «тип путешественника» (`traveler.js`), «на каком море город» (`seas.js`), компактные контуры (`geo-pack.js`), журнал ошибок (`errlog.js`), расстояние Левенштейна с порогом (`text-distance.js`) |
| `scripts/lint.mjs`, `scripts/eslint-html-rule.mjs`, `scripts/style-check.mjs` | проверка кода, правило «данные в разметку — только экранированными», проверка оформления (шкала текста, цвета и слои — переменными) |
| `.prettierrc.json`, `.prettierignore` | оформление кода (Prettier) и что им не трогать |
| `src/main.js` | точка входа: Leaflet, кластеры, стили, приложение |
| `src/data/` | справочники: границы стран, регионы России, города, сведения о странах, объекты ЮНЕСКО (`unesco.json`) |
| `scripts/build-unesco.mjs` | пересборка `src/data/unesco.json` при обновлении списка ЮНЕСКО (точки объектов + файлы «id\|русское название») |
| `src/assets/flags.woff2` | шрифт флагов для Windows; сборка кладёт копию в `fonts/flags.woff2` (адрес с `?v=хэш`), страница подключает его, только если система не рисует флаги |
| `src/lib/geo-pack.js` | компактная запись контуров стран и регионов без потерь; плагин `geo-pack` в `vite.config.mjs` встраивает так файлы, импортированные с `?geopack` |
| `scripts/build-country-travel.mjs` | пересборка `src/data/country_travel.json` (розетки, напряжение, движение, код, экстренные номера) из `scripts/data/` — без сети |
| `scripts/build-seas.mjs` | пересборка `src/data/seas.json` и `sea_shapes.txt` (подписи и контуры морей) из Natural Earth |
| `index.html`, `friends/index.html` | **готовые** файлы — их собирает GitHub Actions, руками не править |
| `borders/` | подробные границы, подгружаются при приближении |
| `fonts/` | **готовые** шрифты — флагов и интерфейса (из пакетов `@fontsource/*`, наборы кириллица / латиница / расширенная латиница); копирует сборка, руками не править |
| `sw.js`, `manifest.json`, иконки | сервис-воркер и данные для установки как приложения; `friends/sw.js` получается из `sw.js` при сборке версии для друзей — руками не править |
| `scripts/build-friends.mjs` | сборка версии для друзей из `index.html` и данных синхронизации |
| `unit/` | модульные тесты Vitest для `src/lib/` — без браузера, пара секунд |
| `tests/` | автотесты Playwright в настоящем браузере |

## Как вносить изменения

1. Загрузить изменённые файлы `src/…` (и другие, если менялись) в репозиторий.
2. Процесс **«Сборка сайта»** (Actions) соберёт `index.html` и `friends/index.html` и закоммитит их.
   GitHub Pages опубликует сайт сам.
3. Процесс **«Тесты»** проверит код, прогонит модульные тесты и проверит сборку в браузере — зелёная галочка у коммита.
4. Процесс **«Релиз»** (`.github/workflows/release.yml`, код — `scripts/release.mjs`): если версии из
   `src/index.html` ещё нет среди релизов, ставит тег `vX.YY` на коммит слияния PR из ветки `vX.YY` и создаёт
   релиз с описанием из PR и вложением `travel-map-vX.YY.html`. Поэтому номер версии меняется в PR вместе с
   кодом, а ветка называется по версии. Прошлые версии — вручную: Actions → «Релиз» → Run workflow →
   «Прошлые версии тоже». Проверить без создания: `node scripts/release.mjs --backfill --dry-run`
   (с `GITHUB_TOKEN` и `GITHUB_REPOSITORY`).

Если загрузить готовый `index.html` вручную, следующая сборка перезапишет его версией из `src/`.

## Локально (если понадобится)

```
npm ci
npm run build          # index.html в корне
npm run build:friends -- --data backup.json   # friends/index.html из файла данных
npm run lint          # проверка кода
npm run format        # оформить код (Prettier); npm run format:check — только проверить

```

## Куда класть новый код

- Вычисление без DOM, карты и глобального состояния (расстояния, разбор файлов,
  форматирование, слияние данных) — в `src/lib/` с `export` и тестом в `unit/`.
  В приложение оно попадает импортом в `src/app/00-imports.js`.
- Всё, что трогает разметку, карту или данные пользователя, — в подходящий
  раздел `src/app/`. Новый раздел — новый файл с номером там, где он должен
  выполняться по порядку.

## Окна и кнопка «Назад»

Окна (`.modal-overlay`, `.story-overlay`) по-прежнему открываются и закрываются сменой
`style.display`. За видимостью всех окон следит `src/app/32a-dialogs.js`: открытое окно добавляет
шаг в историю браузера («Назад» закрывает верхнее окно его же крестиком), переводит фокус внутрь
и держит Tab в окне; после закрытия фокус возвращается на открывшую кнопку. Нижние вкладки телефона
(`44-mobile-nav.js`) пользуются тем же учётом шагов — `historyPushStep()` и `historyBackSilently()`;
напрямую `history.pushState`/`history.back()` для своих шагов не вызывать.

## Боковая панель: вкладки на компьютере и на телефоне

Разделы панели помечены атрибутом `data-mtab` (`add`, `list`, `filters`, `more`). На телефоне их
показывают нижние вкладки (`44-mobile-nav.js`), на компьютере — вкладки над панелью
(`44a-side-tabs.js`: «Добавить», «Список», «Статистика», «Фильтры», «Данные»; выбранная хранится под
ключом `travel-map-sidetab`). Новый раздел достаточно пометить `data-mtab` — он появится в нужной
вкладке в обеих раскладках. Чтобы открыть раздел из кода, вызывайте `mnavShow('list')` и т. п. — на
компьютере она переключает вкладку панели, на телефоне открывает нижнюю. Поле поиска на компьютере
переезжает в шапку панели (`#sideHead`) и возвращается на место на телефоне.

## Проверка кода

`npm run lint` (скрипт `scripts/lint.mjs`) прогоняет ESLint: необъявленные имена, неиспользуемые
функции и переменные, явные ошибки. Разделы `src/app/` проверяются склеенными — так же, как их
собирает Vite, — а номера строк в отчёте указывают на исходные файлы. Процесс «Тесты» запускает
проверку первой: опечатка в имени функции остановит выкладку до того, как сломается карта.

**Оформление кода** — Prettier (`.prettierrc.json`: строки до 160 знаков, одинарные кавычки).
`npm run format` оформляет исходники, `npm run format:check` только проверяет — так делает и
процесс «Тесты», сразу после ESLint. Не оформляются готовые файлы сборки, справочники
`src/data/`, сторонний код и `src/index.html` (`.prettierignore`). Коммит, который только
переформатировал код, записан в `.git-blame-ignore-revs`: GitHub показывает «кто менял строку»
в обход него, локально — после `git config blame.ignoreRevsFile .git-blame-ignore-revs`.

Два правила проекта сверх обычных:

- **Пустой `catch` — только с комментарием**, почему сбой можно пропустить
  (`catch(e){ /* нет доступа к хранилищу — настройка не запомнится */ }`). Неожиданный сбой
  пишется в журнал: `logError('где', ошибка)` (`src/app/00a-errlog.js`, хранение —
  `src/lib/errlog.js`). Журнал — последние 50 сбоев в хранилище браузера (`travel-map-errlog`),
  без содержимого записей; виден в «Проверке данных» → «Ошибки приложения» (там же
  «Скопировать» и «Очистить»). Настройки в хранилище — через `prefGet` / `prefSet` /
  `prefRemove`: нет доступа — не сбой, переполнение — в журнал.
- **Данные в разметку — только экранированными** (`scripts/eslint-html-rule.mjs`). В шаблонной
  строке с тегами и во всём, что идёт в `innerHTML` / `insertAdjacentHTML`, каждая подстановка
  `${…}` должна быть заведомо безопасной: `escapeHtml` / `escapeAttr` / `safeUrl`, число,
  постоянная строка, поле, которое проверяется при загрузке (`id`, `color`, `year`, `month` —
  `sanitizeEntryFields`), встроенный справочник, переменная или своя функция, собранная из
  безопасного, имя с `Html` (готовая разметка). Остальное — ошибка проверки. Если значение
  безопасно, но проверка этого не видит, — пометка с причиной:
  `${n /* html-ok: число */}`, а для помощника, которому передают только числа, —
  `// html-ok-params: причина` перед функцией. Примеры того, что правило пропускает и что ловит, —
  `unit/eslint-html-rule.test.js`.

## Оформление: шкала текста, цвета, слои

В начале `src/styles/app.css` — переменные, и правила пользуются только ими (это проверяет
`scripts/style-check.mjs` в составе `npm run lint`):

- **размер текста** — шкала `--fs-1…7` (11, 12, 13, 14, 16, 20, 24 px); мельче 11 px текста нет.
  Крупные декоративные цифры и значки от 26 px можно числом. Исключение — пометка `fs-ok` с причиной;
- **цвета** — переменные тем в `:root` и `[data-theme='dark']`; цвет с прозрачностью —
  `rgb(var(--…-rgb) / 0.3)`. Числом цвет нельзя ни в правилах, ни во встроенных `style="…"`
  (пометка `style-ok` — для аварийного баннера в `<head>`, которому нельзя зависеть от стилей).
  Цвета рисования на холсте и опции слоёв Leaflet — в коде, сюда не относятся;
- **слои** — `--z-*` (от `--z-map-ui` до `--z-boot`); 1–9 числом — для порядка внутри блока;
- одинаковые встроенные стили — служебные классы `u-*` в конце файла.

## Запуск по этапам и дом

- **Запуск** (`src/app/00b-boot.js`): пока идёт запуск (`booting`), невидимое сразу — статистика
  с учётом фильтров, значок проверки данных — ставится в очередь `idleTask(имя, функция)` и
  выполняется порциями после первой отрисовки, когда браузер свободен. Когда всё досчитано, у
  `<html>` появляется `data-ready="1"` — его ждёт `openApp` в тестах (после `page.reload()` ждите
  его же). Точки подписей стран на «Контурах» считаются при первом обращении.
- **Замеры**: `perfStep('группа')` → `T('шаг')` → `T.end()`; длительности шагов запуска,
  `rebuildAll` и `applyFilters` лежат в `window.__tmPerf`.
- **После правки** (`rebuildAll`) слой записи на карте пересоздаётся или перенастраивается, только если изменилось то, от чего зависит его вид (`layerSignature` в `src/app/09-layers.js`: тип, цвет, статус, «любимое», название, координаты, трек, страна и насыщенность её заливки). Добавляете в слой что-то новое из записи — добавьте это и в подпись, иначе после правки слой не обновится (это ловит `tests/v278.spec.js`: 30 случайных правок против полного пересчёта).
- **Список** (`src/app/15-list.js`) рисуется порциями: 40 строк, дальше по 100 — когда кнопка
  «Показать ещё» подъезжает к экрану (или по нажатию). Строки вне экрана браузер не раскладывает
  (`content-visibility`).
- **Дом** (`src/app/01-map.js`, раздел «Дом» — `src/app/36-home.js`): настройка устройства
  `travel-map-home` (город, координаты, страна), по умолчанию — Москва; в файл данных не пишется.
  После смены приложение перезапускается. Регионы России от дома не зависят (`RU_COUNTRY_KEY`).
  У друзей настройки нет — там дом по умолчанию.
- **Стартовый вид карты** (`applyStartView` в `src/app/01-map.js`): сохранённый вид
  (`travel-map-mapview`) важнее всего; без него на компьютере — весь мир (`WORLD_VIEW_BOUNDS`), на
  вертикальном экране — `phoneStartView()`: наименьший масштаб, при котором мир выше экрана,
  верхний край у 82° с. ш., долгота — медиана городов и середин стран (до загрузки данных — дом).
  Вид ставится при запуске, через 150 мс и после чтения данных, но только пока карту не сдвинули
  (`atStartView()`); сам стартовый вид не запоминается. Проверки — `tests/v280.spec.js`.

## Подложка «Подробная» (векторная)

- **Код:** `src/app/01a-vector-map.js` (включение, тема, запасной путь, «Карта без сети») и `src/lib/vector-map.js` (русские подписи, ключ плитки, план скачивания; модульные тесты).
- **Источник:** OpenFreeMap — `https://tiles.openfreemap.org`, разрешён в политике безопасности (`scripts/csp.mjs`). Стиль берётся с сервера («Liberty», в тёмной теме — «Dark»), подписи с названиями переписываются на `name:ru` → `name:latin` → `name`.
- **Библиотека:** MapLibre GL и мост `maplibre-gl-leaflet` копируются при сборке из `node_modules` в `vendor/maplibre-gl-<версия>/` и `vendor/leaflet-maplibre-gl-<версия>.js` (`vite.config.mjs`) и грузятся только при выборе подложки. Обновили пакет — поменяйте версию в именах в `vite.config.mjs` и `01a-vector-map.js`.
- **Без сети:** сервис-воркер кладёт плитки в `travel-map-vector-<вариант>-v1` (до 1500, вытесняются давно не открытые). Скачанные заранее районы лежат в `travel-map-vector-saved-v1` и не вытесняются. Номер недельной сборки карты из адреса плитки в ключе кэша убирается (`vectorTileKey` и его копия в `sw.js`).
- **Если сервис недоступен:** `setBasemap(mode, { auto: true })` переключает подложку, не трогая выбор человека (`travel-map-basemap`). Время сбоя — `travel-map-vector-down` (`markVectorDown` / `vectorDownSince` / `clearVectorDown`): 6 часов при запуске сразу обычная, первая загрузившаяся плитка снимает отметку. Без WebGL выбор меняется насовсем. Сервис-воркер при ответе-ошибке сервиса (не только при обрыве сети) отдаёт сохранённое. Тесты — `tests/v282.spec.js`, `tests/offline-sw.spec.js`.
- **Тесты:** настоящий сервис из тестов недоступен. `tests/fixtures/openfreemap.js` подставляет стиль, описание источника и настоящие векторные плитки (собираются `geojson-vt` + `vt-pbf`). WebGL в headless Chromium есть (программный).

## Хранилище, импорт и экспорт

- **Профиль высоты** (`profile`) — массив высот в метрах по ходу трека, прорежённый до 40 точек при импорте GPX. Его читают график в карточке, паспорт и экспорт GPX. `normalizeEntryShape` (`src/lib/format.js`) старые пары `[расстояние, высота]` переводит в высоты.
- **Нечитаемые данные** (`loadData` в `src/app/02-storage.js`): исходная строка откладывается в `travel-map-data-unreadable`, сверху — предупреждение `#dataRescue` с кнопкой «Скачать копию». Если места на копию нет, `saveData` отказывается писать, пока человек не скачает копию.
- **Переполнение хранилища:** при записи освобождается только кэш геокодера; карантин записей (`travel-map-quarantine`) — это данные, его не трогать.
- **Импорт JSON:** выбор действия — `askImportMode` (окно `#importModeModal`), не `confirm`.
- **Имена скачиваемых файлов** — латиницей: в некоторых сборках Chromium кириллица в атрибуте `download` превращалась в «download».
- **Обложки** (`covers/`) — не больше ~1920 px по длинной стороне; крупные уменьшать перед добавлением (полноразмерный снимок с камеры весит мегабайты и только тормозит галерею).

## Локальный прогон тестов

Как в CI: `npm run build`, затем `node scripts/build-friends.mjs --data tests/fixtures/friends-sample.json`
(версия для друзей на тестовых данных — иначе тесты версии для друзей откроют старую сборку),
затем `npx playwright test`. Получившиеся `friends/*` не коммитить: их собирает GitHub.
Если браузер Playwright другой версии, путь к нему можно передать в `CHROMIUM_PATH`. Запросы сервис-воркера Playwright перехватывает только с флагом `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` — его ставит `playwright.config.js`.

## Окно для отладки и тестов

Самому приложению глобальные имена не нужны: обработчики навешиваются через `addEventListener`
(кнопки в карточке на карте — `data-popup-act`, фото — атрибут `data-photo`). Для отладки
плагин `debugHook` в `vite.config.mjs` публикует все верхнеуровневые имена одним объектом:
в консоли браузера `__travelMap.allEntries`, `__travelMap.rebuildAll()`.

Под автоматизацией (`navigator.webdriver` — Playwright) те же имена повторяются прямо на `window`,
поэтому в тестах можно писать `allEntries`. У обычного посетителя на `window` только `__travelMap`
(это проверяет `tests/v257.spec.js`).
